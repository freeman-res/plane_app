# Как устроено редактирование задач

Это описание изменений, сделанных перед добавлением проектов. Все пути указаны от корня репозитория.

## Сервер

Код задач собран в `backend/tasks/`:

| Файл | Что делает |
| --- | --- |
| `schemas.py` | Описывает данные задачи и проверяет поля входящего запроса. `TaskUpdate` позволяет передать только изменяемые поля. |
| `router.py` | Связывает HTTP-адреса с функциями сервиса и возвращает 404 для отсутствующей задачи. |
| `service.py` | Принимает проверенные данные и передаёт изменения репозиторию. |
| `repository.py` | Выполняет SQL-запросы к SQLite. Значения передаются отдельно от SQL через `?`. |

`backend/main.py` подключает роутер задач. Старые `backend/routes/tasks.py`, `backend/services/tasks.py` и `backend/schemas.py` больше не нужны.

Запрос `PATCH /tasks/7` с телом `{"title":"Новое название"}` меняет только название задачи №7. `model_dump(exclude_unset=True)` выбирает поля, которые действительно пришли в запросе. Поэтому прежнее описание и статус остаются на месте. Пустой запрос, `null` для обязательных полей и пустое название отклоняются схемой. Для несуществующего номера сервер отвечает 404.

## Flutter

- `app/lib/features/tasks/tasks_page.dart`: кнопка с карандашом открывает форму для выбранной задачи и обновляет список после сохранения.
- `app/lib/features/tasks/task_dialog.dart`: одна форма используется и для создания, и для редактирования; при редактировании поля заранее заполнены.
- `app/lib/core/api_client.dart`: метод `editTask` отправляет `PATCH` с названием и описанием, затем разбирает ответ сервера.

Путь данных: кнопка → форма → `ApiClient` → `router.py` → `service.py` → `repository.py` → SQLite → обновлённый список.

## Проверки

`python -m unittest discover -s tests -v` проверяет создание, частичное изменение, очистку описания, сохранение статуса, удаление и неверные значения. Анализ `dart analyze lib test` прошёл без замечаний. Для Flutter-теста на компьютере пользователя: `cd app`, затем `flutter test`.
