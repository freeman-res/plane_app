# Статусы, дедлайн и приоритет задач

Эти поля реализованы в Python API и SQLite. Интерфейс Flutter пока не изменён: в нём ещё нет выбора статуса «В работе», даты и приоритета.

| Поле JSON | Значения | По умолчанию |
| --- | --- | --- |
| `status` | `todo` — «Сделать», `in_progress` — «В работе», `done` — «Готово» | `todo` |
| `deadline` | Дата в формате `ГГГГ-ММ-ДД` или `null` | `null` |
| `priority` | `low` — низкий, `medium` — средний, `high` — высокий | `medium` |

`POST /tasks` принимает новые поля при создании задачи:

```json
{
  "title": "Подготовить отчёт",
  "description": "",
  "project_id": null,
  "status": "todo",
  "deadline": "2026-12-15",
  "priority": "high"
}
```

`PATCH /tasks/{task_id}` меняет только переданные поля. Например:

```json
{"status": "in_progress", "deadline": "2026-12-20", "priority": "medium"}
```

Чтобы убрать срок, отправь `{"deadline": null}`. `GET /tasks` и ответы на создание и изменение возвращают все три поля. Неверная дата, статус или приоритет возвращают ошибку валидации 422. Статусы можно менять в обе стороны; сервер не навязывает порядок переходов.

`backend/database.py` добавляет столбцы `deadline` и `priority` при запуске сервера, если база создана старой версией. Уже записанные задачи сохраняют свой статус, получают `deadline = null` и `priority = medium`. Текущие Flutter-клиенты продолжают работать с прежними полями, но для отображения и изменения новых значений нужно обновить Flutter отдельно.

Проверка из PowerShell в корне проекта:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```
