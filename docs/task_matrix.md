# Матрица Эйзенхауэра

В приложении появился режим «Матрица» с четырьмя областями: срочно и важно, важно и не срочно, срочно и не важно, не срочно и не важно. Готовые задачи не попадают в матрицу, но остаются в списке и на доске. Текущий выбор проекта, поиск и фильтры действуют и для матрицы.

**Важность:** высокий приоритет (`high`) означает «важно», средний (`medium`) и низкий (`low`) — «не важно» именно для группировки. При этом прежние три значения приоритета сохраняются для сортировки.

**Срочность:** новое поле `urgent` может быть `true`, `false` или `null`. Значение `null` означает автоматическое правило: задача срочная, когда дедлайн сегодня, уже прошёл или наступит в ближайшие два дня. Если дедлайна нет, задача не срочная. `true`/`false` задают срочность вручную независимо от дедлайна. Признак просрочки `is_overdue` остаётся отдельным и вычисляется по дедлайну и статусу.

Задать срочность можно в диалоге создания или редактирования задачи. Кнопка «Переместить» в матрице обновляет `urgent` и приоритет: при переносе в важный квадрат выставляется `high`, в неважный квадрат `high` меняется на `medium`; если приоритет уже `medium` или `low`, он сохраняется.

API задач принимает `urgent` в `POST /tasks` и `PATCH /tasks/{id}`. `PATCH` с `{"urgent": null}` снова включает автоматическое правило. В ответе есть исходное значение `urgent`, вычисленное `is_urgent` и название `matrix_quadrant`. Метод `GET /tasks/matrix?project_id=1` возвращает четыре массива: `urgent_important`, `not_urgent_important`, `urgent_not_important`, `not_urgent_not_important`. Для выполненных задач массивов нет.

При запуске приложения старая база получает nullable-столбец `urgent`; прежние задачи сохраняются и получают автоматическую срочность по их дедлайну.
