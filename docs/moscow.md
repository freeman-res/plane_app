# Планирование MoSCoW

MoSCoW позволяет договориться внутри проекта, какие задачи попадут в текущий объём работ:

| Категория | Значение |
| --- | --- |
| Must | Без этой задачи результат нельзя считать готовым. |
| Should | Важно выполнить, если хватает времени и ресурсов. |
| Could | Желательно, если останется время. |
| Won’t | Откладывается на следующий этап; задача сохраняется. |

В форме задачи выберите категорию, затем откройте вкладку **MoSCoW**. Для работы с отдельным проектом сначала выберите его в боковой панели. На вкладке можно перемещать задачи между группами, в том числе возвращать в «Без категории». Завершённые задачи видны на доске и в списке, но не входят в планирование.

MoSCoW хранится в поле `moscow` задачи (`must`, `should`, `could`, `wont` или `null`); существующие задачи после миграции остаются без категории. Статус выполнения, приоритет, срочность и матрица Эйзенхауэра независимы от MoSCoW.

API: `POST /tasks` и `PATCH /tasks/{id}` принимают поле `moscow`; отправка `null` в PATCH снимает категорию. `GET /tasks/moscow?project_id=1` возвращает пять массивов: `must`, `should`, `could`, `wont`, `unassigned`. В каждой группе действующие задачи отсортированы по приоритету, затем по сроку. Без `project_id` возвращаются задачи всех проектов. При удалении проекта задачи остаются без проекта и сохраняют свои категории.

Учёт участников команды, назначение исполнителей и права доступа пока не реализованы; текущая категория доступна всем, кто использует локальное приложение и его API.
