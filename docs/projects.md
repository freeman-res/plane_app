# Что добавлено для проектов

Проект собирает связанные задачи. Например, можно создать проект «Курсовая» и назначить ему несколько задач. Файлы проекта организованы по функциям: весь серверный код проектов находится в `backend/projects/`, а модель и форма на Flutter — в `app/lib/features/projects/`.

## База и сохранность прежних задач

`backend/database.py` при запуске создаёт таблицу `projects`. Если база создана старой версией приложения, он один раз добавляет к `tasks` столбец `project_id`. При повторном запуске столбец не дублируется. Старые строки остаются на месте с `project_id = NULL`, то есть «Без проекта». Перед изменением рабочей базы была создана локальная копия `backend/tasks-before-projects.db` (игнорируется Git).

| Таблица | Поля, которые используются сейчас |
| --- | --- |
| `projects` | `id`, `name` |
| `tasks` | `id`, `title`, `description`, `status`, `project_id` |

`project_id` хранит идентификатор проекта, а не его название. Поэтому переименование проекта в будущем не потребует менять каждую задачу.

## Серверные файлы

| Файл | Роль |
| --- | --- |
| `backend/projects/schemas.py` | Проверяет имя проекта и описывает ответ API. |
| `backend/projects/router.py` | Обрабатывает `GET /projects` и `POST /projects`. |
| `backend/projects/service.py` | Передаёт операции в репозиторий. |
| `backend/projects/repository.py` | Читает и записывает проекты в SQLite; проверяет существование проекта. |
| `backend/tasks/schemas.py` | Теперь принимает необязательный `project_id` при создании и изменении задачи. |
| `backend/tasks/service.py` | Возвращает 404 при попытке назначить несуществующий проект. |
| `backend/tasks/repository.py` | Сохраняет связь и умеет отбирать задачи по `project_id`. |

Примеры запросов: `GET /projects` возвращает все проекты; `POST /projects` с `{"name":"Курсовая"}` создаёт проект; `POST /tasks` с `{"title":"Написать введение","project_id":1}` создаёт задачу в нём. `PATCH /tasks/3` с `{"project_id":null}` убирает задачу из проекта, сохраняя саму задачу. `GET /tasks?project_id=1` возвращает задачи проекта №1.

## Flutter

`app/lib/features/projects/project.dart` превращает JSON ответа в модель `Project`. `project_dialog.dart` показывает форму нового проекта. `app/lib/core/api_client.dart` отправляет запросы проектов и передаёт `project_id` для задачи. `app/lib/features/tasks/task_dialog.dart` позволяет выбрать проект или «Без проекта». `tasks_page.dart` загружает список проектов и задач, показывает фильтр и после сохранения перечитывает данные с сервера.

Путь данных: **выбор проекта в форме → `ApiClient` → роут FastAPI → сервис → репозиторий → SQLite → обновлённый экран**.

## Проверка

`python -m unittest discover -s tests -v` проверяет создание проектов, связь с задачами, перенос задачи, снятие связи и сохранность старой базы при миграции. `dart analyze lib test` проверяет Dart-код. Для теста Flutter на локальном компьютере: из `app/` выполнить `flutter test`.

## Отображение и удаление проектов

На главном экране каждый проект показан отдельной карточкой, даже если задач в нём пока нет. На карточке видны имя и количество задач. Нажатие на карточку выбирает проект и фильтрует задачи; выпадающий список работает так же.

Кнопка корзины на карточке запрашивает подтверждение. После подтверждения Flutter вызывает `DELETE /projects/{project_id}`, обработчик передаёт запрос сервису и репозиторию, а SQLite удаляет проект. Связанные задачи сохраняются: благодаря `ON DELETE SET NULL` их `project_id` становится `NULL`, и они отображаются в разделе «Без проекта». Удаление неизвестного проекта возвращает 404. После успешного удаления список проектов и задач загружается заново.
